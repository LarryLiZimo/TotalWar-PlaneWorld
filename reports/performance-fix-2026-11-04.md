# 最大规模会战性能修复

2026-11-04。本次修改已进入正式源码，修复高 DPI/大窗口误关缓存及逐兵 Canvas 提交导致的“PPT”，并优化模拟。最大 6,368 人实战在本机 150% 和 200% 显示缩放下均约 **60 FPS**；最密集混战的模拟仍约 **0.7× 实时速度**，不能宣称已全部满速。

## 正式修改

- `src/render.ts`：取消按整幅画面的 `zoom <= 4` 关闭缓存；按每种模型完整身体、脚步、武器旋转与描边范围选择 32/64/128 像素图格。完整图形超过 128 像素的少量近景模型仍用矢量。修正旧图格可能截掉大体型武器、以及更大脚步状态的缓存键碰撞；缓存最多 16 页 1024×1024、8192 个图格。
- `src/sprite-batch.ts`：256 人及以上优先使用原生 WebGL2 实例化精灵。16 层图集纹理数组保存旋转图形，按原 Y 顺序一次提交，再一次合成到主 Canvas；透明度采用预乘 alpha 和线性采样，保留平滑位置与颜色。矢量插入和图格复用前会刷新批次，避免改变遮挡顺序或引用被覆盖的图格。WebGL2 不可用/初始化失败/上下文丢失时保留 Canvas 缓存回退。
- `src/main.ts`：表现最多更新 60 Hz，避免高刷新率屏幕持续占用资源；DPR 改变时保持相同逻辑镜头缩放。Worker 固定步频仍是 20 Hz。
- `src/sim/battle.ts`：目标真实身体包围盒先排除远距离；拥挤度在原有首次采样时刻预热，再用非负代价下界剪枝。上一目标仅作为搜索上界，相同代价仍按原数组顺序决定，保留原生距离计算。近邻先按平方距离粗筛再算角度；近战冷却期间跳过无用攻击区域/遮挡复验，接触与侧背压力照常更新。复用障碍身体边界、避免为纯碰撞阶段构建阵营索引；士气的距离条件在发现合格敌人后提前退出。
- `src/sim/spatial.ts`：保留原顺序和胶囊去重，增加按阵营查询，减少无关候选进入数组和后续循环。
- `src/sim/physics.ts`：圆形接触使用等价快路径，保留几乎重合时的旧稳定法线；同一步的接触恢复系数计算一次。
- `src/performance.ts`：明确显示“绘制提交”，并报告模拟时间/墙钟时间的实际倍速，避免只看 JS 提交耗时误判完整渲染成本。

## 最大规模无界面前后对照

相同打包方式、种子 `20261104`，每套运行 800 步/40 模拟秒；下表取 20～40 秒接战窗口，每组 400 步，包含模拟，不包含绘制。

| 8× 编制 | 初始模型 | 修改前平均/P95 | 最终修改后平均/P95 | 平均下降 |
| --- | ---: | ---: | ---: | ---: |
| 经典对经典 | 6,368 | 89.15 / 113.70 ms | 47.67 / 68.96 ms | **46.5%** |
| 经典对重装 | 5,680 | 78.87 / 89.62 ms | 48.02 / 66.08 ms | **39.1%** |

两套编成每 5 秒对完整可序列化状态做 SHA-256 比较，共 **16 个检查点全部与旧版一致**；结束后各 32 个随机值也一致，诊断异常均为空。没有通过删减人数、降低固定步频或改变伤害/命中规则提高速度。

同一修复过程的较早一次采样为约 37～38 ms/步；后续最终采样为上表数据，未选取较好的一轮代替最终结果。机器负载/频率会使绝对值变化；最后一组交替内核实验中，前一版本两次为 67.19/64.85 ms，最终版本为 60.21 ms，保留全部原始记录。

## 真实浏览器实战

Windows、本机 Chrome 156、ANGLE/D3D11 + Intel Iris Xe，1600×900 CSS 视口。使用实际 Worker 从正常开局运行，没有向 Worker 注入冻结战斗状态，也没有开启 CPU 采样。表中 FPS 来自实际绘制帧的 rAF 间隔，模拟倍速独立记录。

| 正式代码窗口 | FPS | 帧 P95 | JS 绘制提交平均 | 模拟单步平均/P95 | 实际倍速 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 6,368 人，150%，开场约 19 秒 | **60.2** | 16.8 ms | 4.04 ms | 27.31 / 45.0 ms | 0.99× |
| 同场 150%，约 18.9～29.3 模拟秒混战 | **60.1** | 16.8 ms | 6.99 ms | 56.83 / 76.7 ms | **0.74×** |
| 同场 200%，约 29.4～35.0 模拟秒混战 | **60.0** | 16.9 ms | 8.58 ms | 60.74 / 77.7 ms | **0.70×** |

后两个混战窗口没有超过 33.3 ms 的绘制帧间隔，WebGL 错误码为零。150% 窗口约 843 个绘制帧对应 843 次 GPU 批绘制及 843 次 Canvas 合成；从逐兵几千次 `drawImage` 减为通常每帧一次合成。

之前真实浏览器在 125%/150% 下完全暂停也仅 3～4 FPS，GPU/Skia 取证见 [深度 Profile](profile-deep-2026-11-04.md)。该旧窗口与本次持续混战阶段不同，不用它计算严格的整体提速百分比。本机实测也不保证所有硬件、5× 倍速或更长时段都达到同样性能。

## 显示与回退验证

在 3200×1800 真实画布上，对同一暂停画面先用 WebGL2 绘制，再主动丢失 WebGL 上下文，检查 Canvas 缓存回退：

- 画布 **5,760,000 像素**，平均 RGB 通道差仅 **0.00494 / 255**。
- 没有像素的任一 RGB 通道差超过 16；蓝/红兵模像素数差均约 0.02%。
- 上下文确实丢失后，画面继续存在，游戏没有致命错误。

真实像素比较验证了批绘制的位置、颜色、透明边缘与 Canvas 路径接近；另已查看经典对重装、巨兽对游牧的高 DPI 图集画面。新增自动检查覆盖 100%/125%/150%/200% DPI、大窗口、较大兵模/武器的图格边界、阵营索引顺序与清空，以及圆形与零轴胶囊接触的几何等价。
